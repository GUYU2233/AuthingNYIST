# Offline APT and RPM repository bundles

Run native packaging first, then from the project root:

```sh
VERSION=v1.2.3 bash scripts/package-repositories.sh
```

`VERSION` is mandatory. One leading `v` is stripped from artifact names.
Inputs are all `dist/*.deb` and `dist/*.rpm`, regardless of filename. Use a clean
`dist` directory: stale native packages are intentionally included by these globs.
Both formats must be present. Debian architectures supported are `amd64`, `arm64`,
and `all` (included in both indexes). On Debian/Ubuntu install `apt-utils`,
`dpkg-dev`, `createrepo-c`, `tar`, `gzip`, and `coreutils`; signing also needs
`gnupg`. Missing tools or packages produce an error, not a partial-format bundle.

Outputs:

- `dist/authingnyist-apt-repository-1.2.3.tar.gz`
- `dist/authingnyist-rpm-repository-1.2.3.tar.gz`
- `dist/repositories-assets.txt`: the two artifact basenames, one per line.

Extract each archive into its own repository root. The APT archive contains
`pool/main`, architecture-specific `Packages` and `Packages.gz` under
`dists/stable/main/binary-{amd64,arm64}`, and a top-level distribution `Release`
with Origin/Label `AuthingNYIST`, suite/codename `stable`, and SHA256 metadata
checksums generated by `apt-ftparchive`. The RPM archive contains `Packages/`
and `repodata/` generated by `createrepo_c`. No network publication is performed.

## Trust and optional signing

**Default output is unsigned and is not trusted/installable under normal secure
APT or DNF defaults.** Generating metadata does not authenticate the publisher.
Do not use `trusted=yes`, `--allow-unauthenticated`, or globally installed
`apt-key` trust as a substitute for signing.

For signed repository metadata, explicitly choose an existing secret signing key:

```sh
GNUPGHOME=/secure/signing-home REPOSITORY_SIGNING_KEY=FULL_KEY_FINGERPRINT \
  VERSION=v1.2.3 bash scripts/package-repositories.sh
```

Signing runs GnuPG in batch mode; provision the signing agent/key access before
running. A signing failure is fatal. The APT archive then includes `InRelease`,
`Release.gpg`, and `repository-signing-key.asc`; the RPM archive includes
`repodata/repomd.xml.asc` and the exported public key. Verify the key fingerprint
through an independent trusted channel before installing or trusting it.

For APT, dearmor that verified key to a dedicated local keyring, for example
`/etc/apt/keyrings/authingnyist.gpg`, and reference **only** that keyring in the
source's `signed-by=` option. Example after extracting to `/srv/authingnyist-apt`:

```text
deb [arch=amd64,arm64 signed-by=/etc/apt/keyrings/authingnyist.gpg] file:/srv/authingnyist-apt stable main
```

For RPM, repository metadata signing is separate from **package** signing.
This script never changes or signs the input RPMs. Configure `repo_gpgcheck=1`
and a scoped `gpgkey=file:///.../repository-signing-key.asc` for the extracted
repository. Keep `gpgcheck=1` only with separately signed RPMs and their verified
package-signing key. If native RPMs are unsigned, package trust is still missing:
a deployment must explicitly resolve package signing or consciously accept an
unsigned-package policy; a signed `repomd.xml` alone does not make them pass
package signature verification. No ready-to-enable DNF configuration is emitted
that silently disables either check.

Archive compression timestamps and repository metadata dates may vary across
runs; these are offline packaging bundles, not reproducible-build guarantees.
