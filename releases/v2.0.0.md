# v2.0.0（正式版）

这是 2.x 的首个正式版，汇总 2.0.0-dev 以来的可靠性、安全与发行改进。升级前建议备份配置；正式版与 2.0.0-dev 的配置格式兼容。

## 本次重点

### 密码不再默认明文落盘

- Linux 优先把密码写入系统密钥环（freedesktop Secret Service，`secret-tool`），配置文件只保存不可逆的引用令牌；密钥环不可用时才回退到 0600 明文，并在保存时明确提示。
- 密钥环条目丢失（换机、重装、跨账户）不再让程序崩溃或误判为“无配置”：会保留账号与网络设置，只提示重新输入密码；`--doctor` 也会标为阻断项。
- Windows 继续使用 DPAPI，macOS 继续使用权限受限的 0600 配置文件；密钥环与文件权限都不防 root。

### 睡眠/唤醒与切换 Wi-Fi 后自动恢复

- 保活循环检测到系统休眠（时间跳跃超过阈值）或校园网切换后，会重新认证一次，而不是长时间显示“在线”却实际断网。
- 网络变化需要连续两次观测确认，避免瞬时抖动误触发；恢复成功与失败会分别触发桌面通知（Linux）与界面状态更新。
- 失败通知按“每轮失败一次”发送，不刷屏。

### 只读诊断与日志轮转

- 新增 `--doctor`：只读检查配置、权限、密码来源、网络一致性、默认路由、代理变量、DNS、门户可达性与保活状态，不需要密码，不改任何设置。只有会阻断认证的问题才返回非零退出码。
- 保活日志自动轮转（单文件 1 MiB，保留一个备份），并发启动也只轮转一次。

### Linux 托盘

- 新增 `--tray`，基于纯 Go 的 StatusNotifierItem 实现，不引入 cgo 或 GTK 依赖；菜单提供状态、连接、断开、设置、打开日志与退出。
- GNOME 需要安装 AppIndicator / KStatusNotifierItem 扩展；没有托盘宿主时会立即给出可操作的错误，而不是静默运行一个看不见的图标。
- 终端菜单也新增了“开启/关闭托盘图标”，关闭托盘不会登出，也不会停止独立的 systemd 服务。

### 发行与分发

- Release 附件精简为 8 个：Windows EXE、macOS 双架构 DMG、Linux 双架构 deb 与 rpm，以及 `SHA256SUMS.txt`。
- AUR、Flatpak、Snap、Homebrew、MacPorts、Nix 配方、Arch 包、仓库元数据与 shell 补全仍可在仓库内用 `BUILD_EXTRAS=1` 生成，但不再作为发行附件分发。
- 新增 shell 补全生成脚本与漂移检查，供仓库内使用。

### 终端界面

- Linux / macOS 终端界面统一使用 Huh 表单：方向键选择、`/` 搜索、Ctrl+C 退出；每次操作使用独立上下文，中断一次不会污染后续操作。
- 移除了旧的经典 CLI（`auth-nyist`），只保留现代 CLI 与各平台 GUI。

## 主要修复

- 修复 macOS 打包脚本中 `lipo -verify_arch` 的参数顺序错误，导致 App/DMG 构建失败。
- 修复 macOS 打包脚本中被误当作命令执行的中文注释，导致版本注入步骤失败。
- 修复 Darwin 测试误用 Linux `nmcli` 夹具的问题，三平台测试现在各自校验真实命令序列。
- 修复发行附件校验在白名单、校验和覆盖与旧布局残留上的漏洞，并补齐 13 项离线回归测试。

## 已知边界

- macOS App/DMG 仅为 ad-hoc 签名，未经 Apple 公证，Gatekeeper 可能阻止启动；需要在“系统设置 → 隐私与安全性”中由用户自行确认。
- Windows GUI 已通过 CI 原生构建与界面烟雾测试，升级为下载校验后的手动替换，不会静默覆盖运行中的 EXE 或停止服务。
- 不宣称保证绕过所有 TUN / 策略路由 / fake DNS；认证请求只是忽略环境代理并尽可能绑定物理网卡。
- Flatpak / Snap 仅提供构建配方，未完成实际 sandbox 包构建；Homebrew / MacPorts / Nix 未在目标系统做安装验收。未上架官方软件商店或发行版仓库。
- 更新校验和只证明同一 Release 内部一致，不是独立发布者签名；也未提供 Developer ID / Authenticode 签名。

## 验证

本地完整 Go 测试与 `go vet`、`gofmt`、Windows / macOS / Linux arm64 交叉编译、全部打包脚本语法检查、Python 打包测试（Linux 包、配方、Flatpak、Homebrew、补全）与发行附件离线测试均通过。GitHub CI 覆盖 Linux / Windows / macOS 测试、Windows GUI 原生烟雾测试、macOS App / DMG 打包与最终 Release 校验。
