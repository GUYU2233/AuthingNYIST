# v2.0.0-dev（预发布）

这是开发预发布，不是稳定版。升级前请备份配置，在目标系统验证后再用于无人值守认证。

## 采纳社区反馈：修复 TUN 环境下的保活误判

采纳上游 [Issue #4：`keepalive` reads a TCP handshake from the tunnel as proof of connectivity](https://github.com/Palvef/AuthingNYIST/issues/4#issue-5861017414) 的意见，感谢问题报告中的复现、对照测试和修复建议。

- 不再把 TCP 握手成功当作校园网连通的充分证据：TUN 代理可能先在本地完成握手，此时目标服务仍不可达。
- 采用该 Issue 建议的应用层往返验证方向：请求图书馆服务，禁止自动跟随跳转，仅接受 HTTP 302 且指向同源 `/opac/search/simsearch` 的响应，拒绝普通 200、错误页及非预期跳转。
- 配合忽略环境代理、尽可能绑定物理网卡的传输策略，降低代理/TUN 导致的假在线；不宣称保证绕过所有 TUN，也未实现该 Issue 提到的 Windows `IP_UNICAST_IF` 接口索引绑定。
- 已增加 HTTP 响应、EOF、超时等回归测试；真实校园网与 Hiddify/TUN 组合仍需实机验收。

## 其他更新

- CLI 自动识别 nyist-tec / nyist-stu，增加认证状态、JSON 状态及版本检查入口，保护其他已在线账号。
- 校园认证请求忽略环境代理并尽可能绑定物理网卡；不修改系统代理、路由或 TUN，不能保证绕过所有策略路由、VPN 或 fake DNS。
- Windows GUI 启动检测网络和状态、自动检查新版本，窗口及托盘提供更新入口。确认后下载同一 Release 的 Windows EXE 并验证 SHA256，退出托盘后手动替换；不会静默覆盖配置、停止服务或自动安装。
- 增加 DEB、RPM、Pacman 双架构打包，APT / RPM 软件源元数据及可选签名，AUR、Flatpak、Snap、Homebrew、MacPorts 和 Nix 固定版本配方，接入 GitHub / GitLab CI。

## 已知边界

- Flatpak / Snap 提供构建配方，尚未完成实际 sandbox 包构建；Homebrew / MacPorts / Nix 尚未进行目标系统安装验收。未上架官方软件商店或发行版仓库。
- Windows GUI 已通过 CI 原生构建与界面烟雾测试，但尚未完成真实校园网环境中的认证和升级验收。macOS App / DMG 已通过 CI 原生打包验证，仅提供 ad-hoc 签名，未经 Apple 公证，Gatekeeper 可能阻止启动。
- 更新校验和验证同一 Release 的一致性，不是独立发布者签名。自动检查默认查询稳定 Release，开发版不会宣称可靠的新旧比较。
- 前端 EXE 替换不会自动更新开机认证服务的独立副本；服务升级需要单独管理员授权。

## 验证

本地完整 Go 测试和 vet、Windows 交叉编译通过；GitHub CI 的 Linux / Windows / macOS 测试、Windows GUI 原生构建与烟雾测试、macOS App / DMG 打包及 Release bundle 已验证通过。原生 Linux 双架构包、仓库元数据及临时密钥签名路径已验证。

同时修复 macOS 网络命令测试模拟、打包脚本注释及 `lipo -verify_arch` 参数顺序问题，并增加可公开读取的 macOS 打包失败诊断。发布附件以本标签 CI 构建及 SHA256SUMS.txt 为准。
